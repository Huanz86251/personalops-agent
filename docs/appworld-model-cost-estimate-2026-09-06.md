# AppWorld 模型组合与人民币成本估算

核对日期：2026-09-06。范围：只读项目证据、公开资料调研与离线算账；没有调用候选模型、启动新评测、修改模型配置或发布私有数据。用户口述的 F1 Word 按本项目 AppWorld 理解，schedule 按 Scheduler 理解。

## 决策结论

- 最低 API 现金成本候选：智谱 GLM-4.7-Flash 免费版。未证明它能可靠完成本项目 AppWorld，不把免费等同于最省总成本。
- 最值得先测的低价付费主力：Qwen3.7-Flash，北京服务，固定版本 qwen3.7-flash-2026-07-15；单次输入不超过 32K 时，输出比旧 qwen-flash 更便宜。
- 建议优先验证的组合：Qwen3.7-Flash 做执行、摘要和简短报告；Qwen3.7-Plus 做 Scheduler 和最终审核。复杂代码失败后，可将该任务执行/审核升级到 DeepSeek-V4-Pro 思考模式。
- 585 道测试题各尝试一次：上述混合组合中心估算约 133 元；加 30% 调试/重试工作量约 173 元。规划准备 200–400 元较合适，属于预算情景而非置信区间。
- 750 道（含 Train/Dev）各一次：中心约 153 元；准备 200–450 元。多组合、多随机种子及 Skill 优化轮次另外乘算。
- 这些价格描述一次尝试的开销，不保证全部通过。目前没有候选组合在这份工作树上的全量成功率。

## 1. 计费范围与当前接线

AppWorld 原始划分为 Train 105、Dev 60、Test-Normal 168、Test-Challenge 417，共 750；正式两个测试集合计 585。来源：[论文 §3.4](https://aclanthology.org/2024.acl-long.850.pdf)。正式运行仍应冻结所装版本的 task manifest，不能只用论文数量替代清单。

这是模拟 App API 的交互编码任务。一次模型响应可能产生一段 Python，其中循环执行很多次模拟 API；API 次数、代码执行次数、模型调用次数、角色数量是四个不同指标。模拟世界里的 Spotify/Venmo 等操作不需要真实这些服务的订阅或交易费用。官方 grader 本身不是收费 LLM reviewer。

只计算云模型 token 费用；本机 Docker、电费、磁盘与人员排错时间未计入。若租机器，另外加机器小时单价×运行时间。未把赠送 token、套餐赠额和可能无法适用于交互轨迹的 Batch 半价算入基准。

本次读到的源码：

- `evals/appworld/adapter.py:363` 的 run_personalops 创建 General Worker，工具为 appworld_execute，接入规划图；没有创建专用 Code Worker/Code Reviewer。
- `evals/appworld/run.py:26` 仍读取 simple/hard 两组模型，只允许 deepseek/openai/anthropic；创建模型处显式 thinking_enabled=True。新逐角色模型配置与默认关闭 thinking 的设置不能假定已覆盖此评测入口。
- `evals/appworld/run.py` CLI 目前只接受 train/dev，不是现成的全测试集运行器。
- 因此下面 Qwen 混合路由、逐角色 reasoning、全量测试均是待接入方案，不能仅换一个模型名称就声称可跑。报告不实施这些更改。
- 当前默认规划为 2 总步骤、30 规划模型轮次、45 工具调用；轮次不是所有供应商请求总数，额外选择器/摘要/修复和 SDK 重试须由统一用量计量。50–70 次调用的难题预算是规划情景，超出现配置须在未来单独调整。

## 4. token 是怎样累加的

设第 j 次输入包含固定提示 P、已有历史 H_j、工具结果 T_j，则累计输入为 Σ(P+H_j+T_j)。例如 12 次输入分别从 4K 每轮增加 1K，合计 114K，最后一轮仅 15K。累计180K不代表某一请求跨越32K计价门槛。

总费用 = [未命中输入×未命中价 + 命中输入×命中价 +（可见输出+reasoning）×输出价] / 1,000,000。

工具返回不直接按 LLM 输出计费，但下一轮塞进模型时会成为输入。Python 循环处理200项后只打印计数/错误和必要字段，可以显著减少模型轮次及结果回传；不能把200个模拟API调用当成200次模型请求。

以下是估算用的24次典型完整任务，不是从旧trace恢复的精确角色分项：

| 角色/用途 | 请求次数 | 累计输入 | 累计输出 | 理由 |
|---|---:|---:|---:|---|
| Skill选择/路由 | 4 | 12,000 | 1,000 | 仅dynamic模式需要；固定/关闭可减少 |
| Scheduler/重规划 | 3 | 30,000 | 3,000 | 首次规划、结果反馈、必要修正的预算 |
| General执行（含交互代码） | 14 | 112,000 | 10,000 | 查文档、执行、观察、纠错、提交 |
| 简短报告/收尾 | 1 | 8,000 | 1,000 | 可包含Worker最终提交；不一定是独立Reporter |
| Final reviewer | 1 | 12,000 | 2,000 | 根据目标和实际证据验收 |
| 摘要 | 1 | 6,000 | 1,000 | 上下文触发时；非每任务必有 |
| 合计 | 24 | 180,000 | 18,000 | 输出为总计费量，包含有限reasoning |

计划中 Scheduler 通常1–3次，复杂/失败时4–6次；不是每次工具调用都重新规划。表中的14次执行若受单步8轮约束，需要跨两个步骤共享任务；具体分配依运行协议。摘要和选择器的额外请求必须实记。

基准将全部角色输入统一按45%命中计算，便于复算，并不声称每个角色都达到45%。执行连续上下文常比首次规划/独立审核更易命中。无缓存、45%、70%分别作为冷启动、基准、优化后情景。

以Qwen3.7-Flash全角色为例：未命中99K×0.2 + 命中81K×0.04 + 输出18K×0.8，再除百万 = 0.03744元，即3.744分。

推荐混合方案把 Scheduler + Final reviewer 的42K输入、5K输出分配给Qwen3.7-Plus，其余138K/13K给Flash；合计0.121824元/典型任务。这里尚未凭空加入多个Code Reviewer。

## 5. reviewer 和 reasoning 怎么配置

AppWorld现入口：一个General执行角色加规划图最终审核；不需要另加收费模型给官方grader评分。General用Python操作模拟器，不意味着启用了生产项目的Code沙箱审核流程。

未来独立Code交付：一个Worker加一个独立Code Reviewer足以作为默认；首次审核失败后回原Worker修复，再由同一个Reviewer复验。两次审核是同一角色两轮，不是两个并行审查员。最终任务审核负责整体目标，不应再次全文重做代码审查。

若在上述典型任务上额外增加一轮实质Code审查，假设4次模型请求、48K输入、6K输出、45%缓存：Qwen3.7-Plus增加0.10944元；DeepSeek-Pro空闲增加0.20304元。生产Code Reviewer的额外文件、工具schema和测试输出可能使此数继续增加。不要向每一道纯查询AppWorld题都收这笔。

Reasoning建议：

- Skill选择、路由、标题、摘要、结构化报告：默认关闭。必要时直接做结构校验；不要让思维链把JSON输出额度吃光。
- 简单General/API操作：默认关闭，遇到实体对齐、时间边界、多条件筛选时才打开有限思考。
- Scheduler：简单题关闭；多应用依赖/计划失败时采用思考模式，先给足完整结构输出空间。
- Code Worker：复杂聚合、分页、状态变更可启用有限思考；常规脚本先非思考。
- Code Reviewer/Final reviewer：复杂状态变更或关键计算使用思考；短文本收尾无需长推理。

额外20K reasoning的直接输出成本：Qwen3.7-Flash 0.016元、Qwen3.7-Plus 0.16元、DeepSeek-Flash空闲0.09元、Pro空闲0.27元；还可能增加后续历史输入。旧qwen-plus开启思考后输出价从2升到8，不能只估新增思维链而忽略整段输出费率变化。

Reasoning是否值得：用同题对照看官方通过率、总费用和延迟。若计划修复提示本身截掉错误，先修提示/协议；升级大模型不能替代给出正确错误信息。

DeepSeek高峰的相关部分翻倍。Qwen非思考与思考实际输出量不同，固定token表只比较价目，不意味着每个模型都会恰好用同样token成功。

敏感性，以推荐组合585题为例：

- 0%缓存：177.34元；45%：133.36元；70%：108.92元。
- 45%缓存，额外30%同结构工作量：173.36元；工作量翻倍：266.71元。
- 若Flash的所有请求都跨32K并落在32K–256K档，按本组合比例重算约194.80元，未加返工。
- 3组组合×3个随机种子是9次完整工作量，不是一次；300元单轮预算会变成约2700元。
- 成功任务的单位成本 = 全部运行费用 / 官方成功任务数。例：0.05元/尝试、20%通过对应0.25元/成功；0.12元/尝试、60%通过对应0.20元/成功。这些成功率仅为经济性算例。
- 反复重跑同一难题的失败可能相关，不能假定每次成功概率独立，更不能承诺重跑至全通过。

建议准备金：全Flash低价试验80–150元/585题；推荐混合200–400元；DeepSeek Flash+Pro空闲500–900元，高峰约1000–1800元。准备金覆盖估计误差，不等于硬停止上限或实际扣款。

## 8. 公开评测能证明什么

本次读取[官方榜单](https://appworld.dev/appworld/leaderboard)及其[JSON](https://appworld.dev/appworld/leaderboard.json)：

| 方法 / 模型 | Test-N任务通过 | Test-C任务通过 | N/C平均交互 |
|---|---:|---:|---:|
| LOOP / Qwen2.5-32B，2025-04-09 | 72.6% | 47.2% | 17.44 / 22.23 |
| ApsaraLab AgentRL / Qwen3-14B，2026-02-15 | 86.9% | 67.6% | 29.51 / 41.78 |

这些是特定训练/Agent方法的结果，不是直接调用同名基础模型，更不是Qwen3.7-Flash、DeepSeek-V4在我们项目里的保证。Interactions不能直接解释为完整多角色系统的API请求数；榜单没有提供足够的逐模型输入/输出/cache账单来精确重计费。

论文E.8的2024成本为ReAct每题0.70美元、PlanExec1.33美元、IPFunCall0.33美元，均为当时GPT-4o设定；其旧价口径换算仅能得到约140K/266K/66K的等价token规模，不是精确输入/输出分账，也不应套今天汇率作为预算。它们支持“多轮常见为十万级累计token”，不能推导新模型成功率。

另一项直接研究Qwen3-8B的[三角色推理编排论文](https://arxiv.org/abs/2604.11465)报告FP16原始5.4%、编排后8.9%的任务完成率。它说明增加摘要和纠错可改善小模型，但不证明低价小模型已能承担整个复杂流程。

## 9. 缓存与模型升级的具体取舍

当前历史缓存40–44%，故45%基准合理；新供应商/新提示布局尚未测量，应保留0%情景。缓存按输入token份额算，不是“命中的请求数 / 总请求数”。命中也仍需付费、仍占上下文。

固定系统提示、工具schema和角色规则放在前面；任务特有字段和新观察放后面。不要在固定前缀中插入每次变动的时间/随机ID；固定Skill快照，避免无必要的schema重排。跨角色切换的提示不同，跨模型/供应商不能预设共享缓存。压缩会改变前缀，但若减少大量无用上下文，整体仍可能更便宜。

DeepSeek默认自动缓存且为尽力而为，新前缀需要落盘；Qwen支持模型的隐式缓存通常要求至少1024 token相同前缀且不保证命中。来源：[DeepSeek缓存](https://api-docs.deepseek.com/zh-cn/guides/kv_cache/)、[Qwen缓存](https://help.aliyun.com/zh/model-studio/context-cache)。本预算不采用显式缓存0.02元的更低读取价，因为显式创建与保持策略需要单独实现、记账。

适岗判断是优先级建议：

| 角色 | 第一候选 | 升级条件 |
|---|---|---|
| 简短路由/摘要/报告 | Qwen3.7-Flash；免费GLM作对照 | 关键ID、数量、时间或失败原因丢失 |
| General API执行 | Qwen3.7-Flash非思考 | 多条件筛选/分页状态连续出错，启用有限思考或升级 |
| Scheduler | Qwen3.7-Plus；简单题可Flash | 跨应用依赖/验收约束复杂，尝试Pro思考 |
| Code执行 | Qwen3.7-Flash简单脚本，Coder-Flash作对照 | 实际定位困难、状态变更错误、失败重试多 |
| Code审核 | 一个独立Qwen3.7-Plus reviewer | 复杂副作用/计算，使用Pro思考并执行检查 |
| 最终审核 | Qwen3.7-Plus | 关键条件与实际状态不一致时升级，不靠口头自证 |

尚不能说任何候选已“完全承担所有AppWorld题”。目前只能确认旧DeepSeek组合在同一题有官方通过证据；Qwen/GLM是待实测候选。生产代码存在模型配置能力不代表AppWorld适配已完成。

建议未来先用公开训练/开发题做小规模配对：同一任务、相同预算、相同提示和工具，比较Flash、推荐混合、DeepSeek组合，记录官方成功、首轮成功、用量、缓存、reasoning、延迟、schema修复和工具错误。先解决现有结构修复提示和评测入口配置差异，再定全量方案。本次未选择或启动付费batch。
