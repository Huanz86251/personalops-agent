# 飞书机器人底部快捷入口

飞书的消息卡片按钮只能显示在聊天消息里，不能由发送消息的代码固定到输入框上方。想要接近 Telegram 底部键盘的效果，需要在飞书开放平台为机器人配置「自定义菜单」。飞书客户端决定菜单的实际外观和位置，不能保证与 Telegram 的多行键盘完全一样。该菜单主要用于机器人单聊。

在飞书开放平台打开当前应用的「机器人」→「自定义菜单」，启用后建立以下主菜单与子菜单。每个**子菜单**的响应动作均选「发送文字消息」。当前飞书配置页没有单独的发送内容输入框，菜单会发送其显示名称；本地入口会严格按下列子菜单名称映射成命令，而不会交给模型猜。主菜单仅用于展开分组：

| 主菜单 | 子菜单名称 | 本地执行 |
| --- | --- | --- |
| 任务 | 插入任务 | `/insert` |
| 任务 | 替换任务 | `/replace` |
| 任务 | 取消任务 | `/cancel` |
| 对话 | 新建对话 | `/new` |
| 对话 | 查看／切换 | `/list`；随后手动发送 `/switch 编号` |
| 对话 | 当前对话 | `/current` |
| 更多 | 提交 RAG | `/rag` |
| 更多 | 清理记忆 | `/clean` |
| 更多 | 帮助 | `/help` |
| 更多 | 退出输入 | `/exit` |

「查看／切换」只负责列出对话；静态菜单不知道目标编号，不能直接完成切换。只有上表列出的子菜单名称会被本地转换；`未命名`等未知名称仍是普通用户消息。不要选择「推送事件」动作：当前接收链路按文字消息处理菜单点击，没有订阅菜单点击事件。若当前菜单层级达到容量上限，可另建主菜单并添加其子菜单；具体上限以飞书配置页为准。

保存菜单、按飞书要求发布应用版本后，在机器人单聊检查客户端是否显示。若开放平台提供「悬浮菜单」展示方式，可以选择它；不同版本的移动端、桌面端布局可能不同。菜单项不会由本仓库代码自动创建；只更新本地代码并重启机器人，不会在飞书客户端凭空出现底部按钮。

本地配合逻辑：点击「提交 RAG」会按当前发送者开启一次性上传模式；「插入任务」和「替换任务」等待下一条文字；「退出输入」可以取消尚未使用的 RAG 上传及其他输入模式。切换到另一菜单操作时，旧的一次性上传和输入模式也会结束，以免后续文字误入旧模式。用户仍可直接键入 `/rag`、`/insert` 等斜杠命令；`/menu` 显示消息内卡片作为备用入口。普通任务完成后不再自动发送快捷操作气泡。若按需卡片发送被平台拒绝，服务端日志会记录错误码与提示，并回退到文字命令。
