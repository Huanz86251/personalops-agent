# 中文 Web 场景：项目真实工具实测

采样时间：2026-09-06 12:50–12:53（Asia/Shanghai）。不是搜索引擎排名研究，也不是网站长期可用率评测。

## 怎么测的

使用项目实际注册的 `web_search_tool.ainvoke` 与 `fetch_webpage.ainvoke`，没有替换成 Codex 搜索、直接请求替代工具结果或预设返回。搜索返回后，人工选择相关直链，用相同本地文本工具读取，再检查具体字段。当前返回后端为 `google`、区域为 `wt-wt`；没有改配置。无模型 API、登录态、浏览器或 MCP 启动。

共 **16 次搜索、23 次页面读取**，逐项顺序调用，避免本地共享单并发读取工具冲突。每页只读取首个最多12,000字符片段；`total_chars` 是转换后全页长度，不代表全部已读或有效正文长度。没有为了计数把空壳翻完，也没有将长页面未读部分当作已检查。

搜索15次返回候选，1次为 `DDGSException: No results found.`；有结果不等于命中任务。读取23次中3次返回明确工具错误，20次返回文本结构；其中仍有6个地图/猫眼空壳、1个明显乱码页、2个仅见通用导航而没有目标价格的页面、1个包含过期安排的介绍页。余下10页包含可判读的相关正文，**不等于10个原任务验收通过**：例如香港型号规格并不回答大陆价格，交通出口不回答实时路线。

原始工具输入、返回、耗时、UTC时间均保存在 Git 忽略的 `.agent/web-source-probes/20260906T045008_*` 至 `20260906T045322_*`，每份新建、不覆盖旧证据。`scripts/probe_web_sources.py` 可复跑公开查询/URL，输出证据路径与 SHA256；不会调用模型或更改搜索后端。原始页面不复制进公开文档或运行时 Skill。

### 编码问题的单独只读定位

这一项不是修改后的工具成功结果：额外用 HTTP 客户端读取同一个电影博物馆 URL，仅检查响应头、meta 与标题。响应为 `Content-Type: text/html`，没有 HTTP charset；HTML meta 声明 `gb2312`，httpx 默认编码却为 UTF-8。按 GB18030 解码标题可得正确中文。当前 `fetch_webpage` 使用 `response.encoding or "utf-8"` 解码，未读取 HTML meta，足以解释本次乱码。

本轮没有顺手修改读取器的编码或图片过滤逻辑；Skill 与 Reporter 已增加编码障碍分类。后续若修工具，应以 BOM/HTTP charset/HTML meta 的明确优先级、中文旧站样本和现有 UTF-8 页做回归，不能简单把所有页面强制 GBK。

## 搜索方式与完整任务走读

### 1. 场馆到访：确实取得了有用字段

`上海博物馆 东馆 开放时间 地址 交通` 返回官方桌面/移动到访页，也混入另一个馆区的须知。读取东馆具体页后，在同一页得到开放、入口及地铁/公交信息。可回答这些静态到访字段；没有查询用户起点、实时路况或末班车，因此不能进一步声称已规划完整路线。

对照查询 `site:shanghaimuseum.net 东馆 交通 地铁` 没结果；减少字段改为 `site:shanghaimuseum.net "东馆" "开放时间"` 返回5条，包括该到访页。经验不是“永远用 site”，而是先确定实体和官方入口，条件过窄时撤非核心词。两种查询的对比没有验证统计意义或搜索稳定性。

### 2. 影院排片：明确未完成，不包装成成功

`site:maoyan.com 北京 电影院 排片` 返回具名影院链接，但摘要内容出现“暂无该影院的影片信息”“为您推荐附近影院”和其他店的起价。两个真实影院链接都只读到壳。电影博物馆官方页有编码障碍，旅游介绍又是旧安排。

所以本轮**没有取得目标日期的真实场次/余座**，不能推荐其中某个站作为“已验证文本可查排片”。Skill 改为：只有真实浏览器能力且能确认城市、目标店与日期时才尝试动态票务；否则把场次缺口报告给 Scheduler，停止相同文本请求，不用其他店价格填空。

### 3. 餐厅与路线：结果有实体不代表字段可靠

`广州 陶陶居 总店 地址 营业时间` 的搜索同时返回总店高德链接、知乎探店、携程用户记录和包含其他分店的百度搜索摘要。高德具体地点仍是壳，知乎403，摘要分店和时段不能混用。本轮没有核实当前营业、排队和用户起点路线。

`上海地铁 2号线 上海科技馆 首末班 官方` 仍返回百科和第三方时刻表，没有因关键词“官方”就变成官方证据。没有继续扩展为地铁专项实测，因此不新增“某交通网站稳定推荐”的未经验证结论。

### 4. 产品与官方数据：能读也要核对地区和口径

小米查询包含大陆通用购买入口、香港规格及台湾页面；移动北京套餐查询混入河南和重庆资费。官方域名不能替代地区校验。国家统计局的月份+指标查询能定位带日期原文，但还返回累计报告和另一个月份；只将契约所需月份和口径对应到原文。

### 5. 活动与技术：标题的年份/版本不是充分证据

`北京 本地宝 故宫 开放时间 2026` 首条是已经过去的7月27日免费开放活动，不是当前通用规则。中文 Python 查询同时出现3.10中文、latest英文、博客；精准版本路径+接口名能收敛到官方页，搜索标题补丁版本和正文仍有差异。优先依据实际打开的内容和适用期。

## 已写回哪些 Skill

更新 `local-life-search`、`technical-source-search`、`official-record-search`、`product-price-search`、`source-research`，以及 `web-evidence-review` 和 `research-task-planning`。没有继续把各领域合成一个巨型 Web Skill，也没有给未测试的论文网站编造可达性结论。

本地生活策略将地图/猫眼移出文本优先路径；增加场馆正文、本地宝的条件性用途、过期旅游介绍、摘要错配和过窄查询的实测例子。Reporter 要核对字段与实体，并区分乱码、TLS、521、403、空壳与真正登录墙。Scheduler 不再把地图规定为地址/开放/公交字段的默认必经步骤。
