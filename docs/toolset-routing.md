# Worker 能力组路由与一次性补选

## 结论

真实持有业务工具的 General、Web、Code Worker 在第一次模型调用前执行同一条混合路由链：

1. 用 BM25 从当前 Worker 真正可挂载的能力组中取前 3。
2. 用常驻 BCE Cross Encoder 对全部可用能力组重排，取前 5。
3. 用 Reciprocal Rank Fusion（RRF，`k=60`）合并两个排名，去重后最多保留 8 个候选。
4. 独立的 Qwen3.7-Flash 能力选择器只看当前 Step、用户原始请求和这 8 个候选，选择 1–3 个能力组。
5. Harness 按能力组展开真实 LangChain Tools，再叠加该 Worker 固定的控制工具。

生产链不会调用当前 Worker 模型做路由 fallback，也不会在失败时展示全部工具。原来的 `show_all_toolsets` 工具、旧生成式 fallback prompt、同 Worker fallback 方法及其 Step 额度/统计字段均已删除。

Scheduler、Replanner 和 Final Reviewer 不挂载业务工具。Step Reporter 只保留固定的审阅材料读取工具；Code Reviewer 也使用固定审阅工具面，不参加能力组路由或补选。因此 Reviewer 报告只能描述“缺少哪类能力”，不能向 Scheduler 传播猜测的 API、函数或工具名。

## 为什么组合 BM25、Cross Encoder 和小模型

- BM25 对“上传”“飞书”“读取本机文件”等稀有但决定性的词更敏感。
- Cross Encoder 能理解整句语义，弥补同义改写和词面不一致。
- RRF 只融合两个排名，不直接相加不可比较的原始分数。
- 小模型负责判断能力的包含关系、组合与先后依赖，例如“查网页 → 生成文件 → 发给用户”。它只选能力组，不执行任务，也看不到具体 API 目录。

BM25 或 Cross Encoder 单路异常时，另一条召回仍可工作；两路都无有效候选、选择器输出非法结果或没有合法选择时，Worker 只保留收尾控制工具，不扩大权限。

## 一次性能力补选

每个 Worker 固定看到控制工具 `request_additional_capabilities`。它不是“显示全部工具”，而是一个有证据、只允许一次的补选申请：

- Worker 填写未完成目标、缺少的能力类别、当前能力不足的事实依据，以及 `U1`、`S1`、`C*`、`E*` 引用。
- Harness 先解析引用，拒绝不存在或无资格的证据。
- 独立 Qwen3.7-Flash 看到固定顺序的完整能力目录，以及当前 Worker 实际可挂载的剩余能力；它只能从剩余可执行组中补选 0–3 个。
- 补选成功后，原能力继续保留，新能力追加到相同 Step 的路由缓存；不会替换原工具面。
- 若没有匹配能力，Harness 保留已有证据并要求 PARTIAL/FAILED 收尾。
- 同一 Worker 第二次申请不会再次展开目录，而是确定性触发现有 finalization 链，只能基于已有证据收尾。

补选控制调用不消耗业务工具额度；真正新增的业务工具调用仍受原 Step 预算、角色白名单、审批和沙箱约束。

## 能力卡与权限边界

每个 `ToolsetSpec` 固定声明：

- 稳定组名与短描述；
- BM25 / Cross Encoder 使用的正向能力文本；
- required / optional 工具名称；
- 是否独占；
- 选中后给执行模型的工作规则。

真实参数 Schema 始终来自工具对象，不复制到能力卡。相关性路由只缩小候选，不能授权工具；角色白名单、Host 文件审批、飞书导出、Docker/浏览器隔离仍由 Harness 执行。

独占能力组不能与其他业务能力组叠加。更宽能力组覆盖窄组时，Harness 会去掉重复组，但不改变权限。

## 缓存与可观测性

路由缓存键由稳定的 Step 查询、用户请求窗口和真实工具签名组成。同一 Step 的工具结果不会导致重复路由；工具池变化时旧缓存失效。一次性补选会在原缓存条目上追加能力，不改写先前选择。

Trace 中应能看到：

- `bm25_top3`
- `cross_encoder_top5`
- `rrf_union`
- 专用选择器最终选择
- 初始挂载与补选后的能力组
- 补选证据、是否命中、是否被强制收尾

正式评测至少记录各能力组 Recall、Macro/Micro F1、过路由率、漏路由率、补选触发率、补选成功率、P50/P95 延迟和最终任务成功率。当前手写测试与两次真实运行只能证明链路接通，不能代替冻结测试集上的路由质量评估。
