## 我做什么，用户练什么

我承担环境适配、代码、诊断工具、受控实验、报告整理和逐项解释。用户每个阶段至少参与一段 20–30 分钟的轨迹讲解：
1. 先看任务和实际观察，自己指出首次错误决策。
2. 提出一个可检验假设，解释要改 Skill、schema 还是执行策略。
3. 看对照结果，说出为什么保留或回退改动。
4. 不看文稿复述一次，再接受追问。

不是每条 span 都让人手读。开发阶段所有 trial 先跑确定性检查；失败、异常慢、异常贵和缺失数据进入人工队列，再抽样检查成功案例防止误判。模型评审可以辅助失败分类，但不能替代官方判分；抽样人工核实评审器本身。
不得对最终 Test-N/Test-C 使用这个错误分析流程来继续调优。公开测试 split 的限制以固定版本 AppWorld 官方规则为准。

## 一张案例卡片

- 任务类别：使用 Train/Dev 或自拟示例，保护许可与个人隐私。
- 预期效果：用可验证的结果描述。
- 首次偏离：定位 trace/span，但不公开私人原文。
- 证据：看到的输入、返回状态、预算与动作。
- 假设：例如错误提示未告诉 Agent 哪个参数非法；尚不是结论。
- 修改：只改变一个机制，记录版本。
- 验证：同题同模型同预算的前后结果，再检查其它未用于编写该规则的开发案例。
- 副作用与决定：新增 Token、延迟、失败迁移，以及保留/回退。
- 泛化：最终在冻结配置的独立测试上看汇总，不把调过的例题当最终成绩。

## 实验纪律

主要组：
A = 完整可运行基线，有正常工具与文档入口，无新增任务 Skill。
B = A + 人工 Skill。
C = A + SkillOpt 产出的 Skill。
时间和预算允许再做 D = B + 工具描述改进，以及 E = C + 同一工具改进；不能混作纯 SkillOpt 收益。

模型、temperature、总预算、工具接口、世界初始化和任务清单一致。更换模型是另一个实验因素。
每次 trial 隔离记忆/文件/数据库；禁止上一题答案泄漏给下一题，不能使用真实私人账号或生产工具。
记录 AppWorld 版本、数据 split、任务清单、重复数、随机性、全部失败（含超时）和成本口径。
SGC 是同场景不同变体全部成功的比例，不是同一道题重复运行成功率。取子集时不能随便截断场景再称完整 SGC。
最终比较使用冻结 baseline 和冻结优化版本；预先限定比较组，不能看测试成绩后挑最好的组再改。
Token 计数按已识别云端调用去重；执行成本、优化成本和判分成本分别报告，缓存 Token 口径一致。本地推理成本不当成免费。
开大批量前先用少量试跑估计成本：案例数 × 组数 × 重复数 × 实测平均花费，另留重试/优化预算；不自动使用无上限 API 预算。
改善写百分点和任务分母，附不确定性或重复结果。无提升如实报告，不承诺到达某个成功率。

AppWorld 要求的 Train/Dev/Test 使用边界与发布限制见 [官方仓库](https://github.com/StonyBrookNLP/appworld)。
SkillOpt 是对自然语言 Skill 的优化；适配器需要接真实 PersonalOps rollout，不是只演示另一个玩具 Agent。[SkillOpt](https://github.com/microsoft/SkillOpt)

## 十天结束的验收标准

- 至少一个可复跑 AppWorld 实验及其真实成绩，清楚标注全集/子集和基准版本。
- 一组公平的优化前后对照；如果未提升，给出负结果和可信原因，不编数字。
- 三张完整案例卡，至少包括一次无效/有副作用的改动。
- 一份质量、Token、延迟、预算与错误分类报告。
- 能解释状态恢复、工具契约、Skill 选择/优化、上下文取舍、验收隔离和泛化边界。
- 能不依赖我代答完成 5 分钟演示和追问。

这是一份共同推进的工作与训练安排；当前没有设置定时任务或承诺在用户不在时每天自动运行。每次继续都按已有证据推进。


## 后续待讨论方向（未排期）

后续探索异步、事件驱动的 Agent：允许用户连续输入多条请求，将输入与执行进度表示为事件，按事件类型、优先级和任务关系决定排队、穿插执行、暂停/恢复或取消/替代，并保留事件与 trace 的关联供评估和回放；先讨论安全中断与状态一致性，不预设它是 SkillOpt 的必要前置，也不立即做全量事件化重构。
