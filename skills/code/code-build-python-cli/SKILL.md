# Python 与命令行实现

## 先确认可调用接口

从 code_task 和真实调用者确认模块路径、函数签名或 CLI 参数、输入编码、stdout/stderr、退出码和返回类型。检查现有解释器、依赖声明、测试配置及工作目录。契约缺失时采用项目已有约定并标注假设；不擅自把同步接口换成异步或把导入模块变成执行脚本。

## 实现可独立验证的核心

将核心行为与参数解析、文件和网络边界分开，但小任务不另建框架。模块导入不应顺带启动服务或修改用户文件。按照约定处理非法参数和异常；不要 catch-all 后返回正常退出码。机器可读 stdout 不混入进度日志；涉及 JSON 时保持可解析。复用已有依赖，不为小功能安装大型库；断网沙箱不能依靠临时联网补环境。

## 自测顺序

1. 用实际解释器运行最小公开入口，检查返回内容而不仅是“没报错”。CLI 用子进程检查真实参数解析、stdout/stderr 与退出码，不能只测内部函数。
2. 增加与要求相关的空输入、非法参数、Unicode、边界数值或受控依赖失败。时间/网络在外部边界替代，核心计算保持真实。
3. 先跑目标测试，再跑受影响模块。检查收集数和跳过项；测试没收集不能算通过。依赖缺失、导入路径错与实现缺陷分别报告。

若导入失败，先检查目录、包布局和解释器，再用项目约定入口；允许明确且可复现的入口路径设置，但不能关闭校验、吞异常或篡改测试让失败消失。交接时写明源码路径与导入条件：Reviewer 默认在 /review，不继承 Worker 的工作目录和临时状态。

本机镜像实测有 Python/pytest/Node，没有 Pydantic/Playwright。需要额外依赖先检查镜像与已交接资源；默认断网，不能按宿主已安装的包推断容器可用，也不能让 Reviewer 无依据联网 pip install。纯标准库可满足契约时无需强加框架；契约明确依赖缺席则报告阻塞。

## 交付证据

交付可复跑入口、requirement ID、结果与限制。CSV实测的成功路径检查stdout JSON中的written整数；非法配置检查退出2与stderr，并重读输入确认未改。不要让一条“进程退出0”概括成功和失败分支。没有运行的检查明确标为未运行。
