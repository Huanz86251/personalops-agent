# 文件生成与转换

## 固定输入输出约定

核对 code_task 的文件入口、编码、分隔符、列名/键名、排序、空值、重复记录、非法行处置、目标相对路径及覆盖规则。只把明确要求作为 MUST。当前 Docker 输入 /handoff 只读，候选/交付文件写 /workspace；/tmp 是临时目录，不作为跨角色交接。不要假设存在 /artifacts，不把容器路径当用户电脑路径或自行发送文件。

## 用小样本确定行为

先构造能人工核算结果的样本，包含有效与应排除记录，再增加当前格式易错的分支，如中文、含逗号/换行的字段、空文件、重复键或损坏输入。使用格式解析器而非手工拼接 CSV/JSON；逐项定义“拒绝整批”还是“跳过并报告”，不能静默丢数据。

## 写出与失败策略

在分配的可写位置工作；默认不覆盖未授权的已有文件，不扩大到递归处理整个目录。批量写入注意同名碰撞与部分成功，按契约提供可区分结果。需要避免半成品时先写临时文件，验证成功后再发布；清理只针对本次创建且定位明确的临时文件，不删除用户输入。只在任务确实要求时引入流式处理或恢复机制。

## 验证必须重读

执行真实转换后，用对应读取器重新打开输出，核对记录数、筛选结果、字段值、顺序、编码及契约要求的元数据。再检查失败路径下原始文件是否完整、目标是否留下可被误认成功的半成品。文件存在、字节数非零和工具返回成功都不等于内容正确。

## 交接

将产物、入口、预期/实际和未验证项放入现有提交字段。实测CSV用带中文、逗号/换行和空格路径的样本经真实CLI写出再解析，确认字段未被手工分隔破坏；拒绝覆盖时核对原目标字节未变。此证据支持数据格式，不支持办公软件视觉排版。Reviewer应能仅凭入口和契约复跑。
