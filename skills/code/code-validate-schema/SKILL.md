# 结构与语义契约实现

## 建立边界矩阵

先检查实际容器依赖。本机镜像实测没有 Pydantic；Schema 是业务约定，不自动意味着必须安装某框架。标准库足以实现用户契约时直接在入口校验；若用户或项目明确要求第三方库，缺依赖就报告并保留条件，不用宿主环境替代容器验证。

读 code_task、现有 Schema、一个真实生产者和消费者。列出关键字段的类型、必填、是否允许 null、默认值、取值范围及未知字段策略；检查跨字段条件和版本兼容要求。缺失、null、空串、零和 false 是不同输入，不用 truthiness 统一处理。只有契约允许时才强制转换类型。

## 让约束真正被执行

确认 Schema 所属版本和运行库行为，在实际入口调用验证器；只生成 JSON Schema 或在提示中写字段名不代表运行时已校验。JSON Schema 的 properties 不会自动让字段必填，也不默认禁止额外字段；按契约配置 required 与 additionalProperties。对于 Pydantic 等使用真实解析/导出方法验证，不假设不同版本行为相同。

## 测试正反例

先跑最小合法对象和完整合法对象，再按风险选择缺必填、错误类型、未知枚举、边界值、额外字段和跨字段冲突。对每个拒绝分支检查调用者可观察的错误；不能只 assert 任意异常。涉及持久化/消息交接时做“构造 → 序列化 → 真实消费者读取”，确认别名、默认值、日期等没有丢失或改义。

## 变更与兼容

新增必填、收紧范围、禁止旧字段都可能破坏旧数据。任务要求兼容时提供旧样本读取与新输出检查；任务没有授权迁移时不要批量重写存量数据。缺陷修复应在最靠近真实边界的位置完成，不能为了测试过关让模型任意接收对象。

## 交付

报告契约差异、调用者和正反例证据。CSV实测通过真实CLI验证 minimum_amount：0合法，缺失/null/bool/字符串/额外字段拒绝。用 `if not value` 会误拒0，宽泛数字类型检查又可能接收bool；要检验接受与拒绝两侧，而非只生成一份Schema文本。
