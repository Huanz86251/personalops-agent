# 验证状态转换与恢复

本策略补充一般行为验证；只应用到当前 code_task 涉及的状态行为，不借审核增加新的一致性或幂等要求。

## 确定状态与不变量

从契约及公开接口列出相关初态、事件、允许的终态和可观察副作用。分清内存状态与持久化记录、事件 ID 与业务对象 ID、发起操作与操作完成。找出必须保持的不变量，例如终态不能被旧事件覆盖，或同一任务的已完成步骤在恢复后不重做。

## 按触发风险选场景

- 正常转换：从合法初态执行完整路径，断言最终状态、返回结果和相关持久化值。
- 重复输入：在任务声明需去重或幂等时重放相同事件，核对记录与副作用次数；不同事件不能被误判为重复。
- 乱序或旧版本：若接口接收版本/顺序信息，先送新状态再送旧输入，检查是否按契约拒绝或忽略。
- 失败与恢复：只在允许的测试环境于关键边界注入失败，重建执行对象或重新打开临时存储，检查继续位置和剩余工作。对象还在同一内存中不足以证明跨重启恢复。
- 取消与并发：当前功能支持时，用受控事件/屏障安排交错，检查取消后的写入、终态唯一性和相互覆盖；不要依靠随机 sleep 赌时序。

选择能击中当前实现风险的场景，无需生成全部组合。时间相关逻辑优先使用可控时钟；并发问题需要构造实际交错，仅重复顺序调用不能证明并发正确。

## 区分模型结果与外部事实

使用真实状态存储或隔离替身模拟外部边界，在该边界计数实际副作用。模拟测试只能证明所模拟的条件，不代表已验证真实服务投递或网络行为。不能安全注入的故障应标为未覆盖。

缺陷报告写清“初态 → 事件序列 → 预期终态/次数 → 实际终态/次数”，附复跑入口与关联要求。把结果交给既有审核协议；无需另造一份状态报告 Schema。

## 小例子

恢复任务先重建对象再验证，不只在一个存活对象调用两次。本项目Code离线回归实际覆盖“暂停于Reviewer→重建运行时→继续原候选”；因此检查应绑定候选版本、恢复角色和发布次数，而非只看返回COMPLETED。外部服务由替身模拟，这不证明真实服务恰好投递一次。
