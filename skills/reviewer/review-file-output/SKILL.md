# 文件结果独立验收

## 明确应交付什么

从 code_task 确定目标文件、格式、编码、列/键、筛选、顺序、空值及错误处置要求。独立构造小样本并手工确定预期；不能把 Worker 的输出作为唯一真值。将内容正确、文件可解析、展示正确和已向用户交付分别判断。

## 正常与风险路径

在 Reviewer 允许的测试目录运行真实候选，不修改产品或覆盖用户数据。重读结果，核对实际记录与字段，不只检查存在、大小、扩展名或写入函数被调用。按格式风险混入中文、分隔符/换行、空数据、非法记录或重复项，检验契约要求的跳过/整批失败策略。

当前 Docker 实测 Reviewer 能读 /workspace 中 Worker 生成的 CSV，却不能改写该目录。独立用例把输出传到 /review 的本轮测试目录，不能直接照抄 Worker 输出到 /workspace 的自测命令后把只读错误判为产品故障。/handoff 原始输入也不就地修改；临时副本只包含所需测试数据。

有覆盖或批量行为时检查已有目标处理、同名碰撞、失败留下的半成品及原始数据是否仍完整。没有授权破坏性操作时使用临时夹具模拟，不能在真实用户目录验证删除。对于复杂办公格式，解析数据不等于视觉布局验收；无相应工具的展示要求保留未验证。

## 判断失败属于哪里

先核对输入格式、编码、路径和调用方式是否符合契约。自己把分号 CSV 当逗号读取是验证错误；候选遗漏合法行是产品缺陷；缺少可用读取器是环境障碍。不要用“文件打不开”统称所有失败。检查半成功结果是否被错误提交为完整产物。

## 给出可复查交接

按 requirement ID 报告输入、预期/差异与命令。实测中Reviewer读取Worker CSV成功，改写/workspace失败；将独立输出指定/review后测试可执行。先修测试输出位置再评价产品，不要求Worker放宽共享权限。确认版本后沿既有发布协议提交，容器文件存在不代表宿主发布或外部发送完成。
