# 电影排片与影院场次

本 Skill 只处理电影信息和只读场次查询。与其他 Web Skill 互斥；若用户还要影评或从出发地导航，由 Scheduler 拆成单独的 Web Step。本 Step 不因查场次而自行登录、选座、购票或付款。

## 固定身份与时间

从用户原话提取影片、城市/区县、影院分店、观影日期/时段、语言/制式/影厅和所需字段。相对时间按本轮时区落到日期；“今晚”还要排除查询时刻之前的场次。城市不明时不能采用票务站默认城市，同名翻拍片要核对年份/主创。只找影院名单时不强制收集全部影片和余座。

影片介绍页、影院列表、搜索摘要只用于定位，**不能证明指定日期、指定影院有指定影片的场次**。直接证据必须来自日期已核对的排片表或影院详情页，能同时读出影片、分店和开场时间。

## 优先使用排片工具

这四个工具由 `MOVIE` 工具组提供；可用时优先调用。它们只读猫眼当前公开的影院排片，返回查询日期、来源、查询时点和覆盖状态；调用工具不需要浏览器或登录。按用户已有信息选择最短路径：

- `list_cinemas(city)`：只问当地有哪些影院，或影院名称模糊时先取得正式名称。
- `get_cinema_showtimes(city, cinema, date)`：指定影院在指定日期的全部影片、场次和逐场公开票价。影院简称唯一匹配时自动解析；不唯一时按候选名称再调用。
- `list_city_movies(city, date, genre="")`：列出指定日期当地有场次的影片及类型；“明天有什么爱情片”可填 `genre="爱情"`，再按用户选择的影片查场次。类型来自猫眼影片描述，不据类型推测质量或推荐程度。
- `get_movie_showtimes(city, movie, date, after="")`：指定影片在当地各影院的场次和逐场价格；唯一的片名简称自动解析，“今晚”须填当前时间后的 `after`。片名不唯一或查无当日排片时，读取候选影片和覆盖状态，必要时再调用 `list_city_movies`。

询价直接用 `get_movie_showtimes`；不需另调价格工具。工具内部会查询多个影院，但 Agent 只需一次工具调用；名称有歧义时才进行第二次调用。`price_cny=null` 表示公开价格的动态字体未可靠解码，不能猜价。工具不提供余座、已订票数、上座率或热度；不能由排片量或票价推断这些信息。影院清单只覆盖猫眼当前列出的影院，`complete_for_listed_cinemas=false` 或有 `errors` 时不能声称查遍全城。

## 有界查找：搜索故障立即换路

排片工具连接失败、数据缺失，或用户需要核验其他来源时，再用 `web_search` 查“城市/区县 + 影片 + 日期 + 排片”。`web_search` 会先查 Google，并在主后端失败时自动回退百炼；若两个后端均报错，这是**搜索工具失败，不是无场次**，不要换几个近义词反复调用同一故障链路，也不在执行中申请浏览器兜底；改查另一个具名公开文本来源，仍失败就如实提交缺口。若搜索正常但无匹配，可放宽一个非用户硬条件再查一次，仍无结果就换其他具名公开来源，不无限试词。

需要网页补证时只发起一次有计划的并发检索，不连续提交同义词。主查询锁定“城市＋影片/类型＋日期＋排片”，最多再补两条真正不同的角度，例如影院官方场次与另一公开票务来源：`web_search(query="<城市> <影片> <日期> 排片", alternative_queries=["<影院全名> <影片> <日期> 场次", "<城市> <影片> <日期> 票务"])`。任一分支已经给出匹配城市、影片、日期和开场时间的直接证据，就用该结果回答并停止；只有明确缺少用户要求的 MUST 字段，才读缓存下一页或换一组更精确的词。

猫眼是可选的公开来源，不是唯一来源。上述工具读取猫眼网站当前使用的公开数据接口，并非猫眼官方承诺稳定的开放 API。本 Skill 的普通排片查询不依赖 Playwright：优先使用排片工具，其次使用 `web_search` 与可静态阅读的公开来源。只有用户原始请求明确要求页面点击/筛选操作，且首次路由已挂载 BROWSER_AUTOMATION 时，才可操作本次搜索或页面实际给出的链接；所有 ID、链接及参数必须来自本次页面。

示意流程（变量值均须从本次真实页面取得）：

```text
list_city_movies(city="<城市>", date="<日期>")
# 指定影片时改用 get_movie_showtimes；指定影院时改用 get_cinema_showtimes。
# 排片工具故障或覆盖不足时，最多用一个收敛查询核对其他公开来源：
web_search(query="<城市> <影片或类型> <日期> 排片")
# 仍无法核实就提交缺口，不补选浏览器。
```

## 选择日期、逐场核验与返回

在排片页选用户指定日期，不因页面默认“今天”就忽略用户所说的“明天/周末”；影院详情页常同时展示多个日期，先确认所选日期，再从**该日期下目标影片**的行读取开场时间。若用户问“今晚”，检查时间仍晚于查询时刻。每条场次绑定“影片—城市与影院分店—日期—开始时间—版本/影厅（若要求）—页面 URL”。例如页面显示“今天 9月18”，影片标题在该日期下，行内是“19:40 22:32散场”，只能把19:40作为开场；日期或影片不匹配时不能取这行。这是格式教学例，不能作为本轮排片事实。

售价须是同影院、同场、同条件的可读数字。猫眼若用私有字形显示售价，就单列“票价未核实”，不猜字形、不拿别院起价填空；不能因为浏览器可能渲染字体就为普通排片补选浏览器。匿名公开排片可读不意味着余座或优惠结算可读。特别检查“暂无该影院影片信息”“附近推荐”，不得把推荐店当目标店。

若已核实两家，就报告“目前核实到两家”及各自链接，不声称全城只有两家；用户要求全部场次时覆盖目标列表/分页，做不到则明确非穷尽。目标日期确无场次须有覆盖地区和日期的可靠依据，不能由搜索报错、单个空页或几家无场次推出。确实查无今天场次且用户在寻找可看选项时，可以再查**明天作为明确标注的备选**，但先如实说明今天的结果；用户只允许今天时不擅自改日期。

证据足以回答就提交，不为不可读的非必需票价循环搜索。向 Reviewer 引用实际排片工具调用或静态来源读取调用，使其看得到片名、日期和场次；只有首次路由已挂载浏览器时，才可引用 `browser_snapshot`。最终答复分开列已核实场次、未核实的票价/余座，附来源与查询时点。只询价不选座锁位、不购票、不联系影院。
