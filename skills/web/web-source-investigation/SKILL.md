# 跨领域证据调查

## 查询与判断

把任务拆成待证实事实，标出主体、日期、范围及缺失字段。每次检索应解决一个缺口。初次发现可在同一个 `web_search` 调用里提供主查询和最多两组互补关键词；三路会并发执行，每路先显示3条。不要为三组关键词连续调用三次工具。结果偏题先改词或限定域名；相关但覆盖不足时，把返回的 `next_page_ref` 原样放进 `continue_refs`，优先读取同一次上游响应的本地缓存。缓存耗尽后仍缺证据，才用更精确的新关键词重新检索。`Q1/Q2/Q3` 只是查询分支；交接具体网页事实时引用结果中的 `source_ref`（首批为 `WA1–WA3`、`WB1–WB3`、`WC1–WC3`，翻页沿用同一前缀继续编号），不要用Q编号或整包搜索调用代替单条来源。保留中文实体和英文专有名词，不把相同查询反复翻译当成新调查。

优先对该事实负有直接发布责任的来源。转载追原文，经验内容核对作者、日期和证据；营销、拼接和无出处页面降级，不能按域名一律判真伪。搜索摘要用于定位，关键结论核对原页。

## 按页面状态换路

有 fetch_webpage 时先读静态正文小段；相关内容未读完才沿 next_index 继续，每段会重新抓取。只有导航、图片编码或模板时先找正文直链或其他公开文本来源。只有首次路由已因用户明确的页面动作而挂载浏览器时，才按观察到的控件操作；不在执行中为读取更多内容补选浏览器。HTTP 成功与下载成功均不代表内容已验证。

普通事实查询遇到登录墙或 JS 正文不可读，优先同一发布者的公开材料或可信替代源；这不是执行中申请浏览器的理由。明确验证码/403/429 不反复刷新或绕过。用户原始请求明确指定的账户操作，只在首次路由已挂载浏览器时按既有授权流程处理。

先看“目标字段是否存在”，不是只看字数或HTTP成功。壳页换渲染方式，连接故障换发布入口，过期内容找同实体新公告；每次改变一个能补证的条件。正文有登录按钮不等于必须登录。长导航后可能真有正文：有匹配标题/直链且返回还有内容时可定位后段；整页仅图片编码则不机械翻完。

实测：ZOL参数页前12,000字符多为导航，后段才有M650-M参数和参考价。当前普通调查应使用 `fetch_webpage` 的目标区间定位正文并引用真实工具结果，不因长导航补选浏览器，也不能只交整页开头或自己的摘抄。Reporter不继承完整网页历史，长结果被截断后可能看不到核心字段。

## 冲突与收敛

冲突先核对版本、地区、单位及发布/事件时间，再判断是否确实矛盾。同稿转载不算多份独立证据。保留“结论—URL—定位—范围—缺口”，不抄整页。第一次并发搜索命中足以覆盖当前标准的来源后立即结束，不默认继续翻页或启动第二批检索；只有某个 MUST 仍缺直接证据时，才针对该缺口继续。原文不可读时明确缺证，不能由摘要补细节。
