# 电影评价与影评

只处理电影评价，不把评价页、评分或“想看人数”当作影院场次证据。若用户还要求查今晚在哪里看，由 Scheduler 拆成另一条电影排片 Web Step；本 Skill 不负责选座、购票或账号登录。

## 锁定同一部电影

从用户原话提取片名、上映年份、导演、主演、国家/地区或版本。片名相同、翻拍、重映、电视剧与电影同名时，先用上述字段核对条目；不能因为搜索结果排第一就选它。用户只要“不剧透的口碑”时，评价内容和最终答复都避开剧情关键转折。

先用一次并发搜索定位允许使用的公开评价来源。主查询锁定影片身份和评分，两个可选分支分别寻找观众评价与专业影评，例如：`web_search(query="<片名> <年份或导演> 评分", alternative_queries=["<片名> 观众评价", "<片名> 专业影评"])`。三个分支是不同口径，不是同义词改写；通常读到一个可靠评分条目和少量可见正反观点就足够生成有边界的总结，不为凑更多评论再搜。搜索摘要只用于定位，不能作为评分和评论观点的唯一依据。若搜索后端报错，不反复改写近义词刷同一后端，改用其他公开文本来源或如实保留评分/评论缺口，不在执行中申请浏览器兜底。

示意流程（条目 URL 只能取自本次真实搜索/网页，不要照抄旧电影 ID）：

```text
web_search(query="<片名> <年份或导演> 评分", alternative_queries=["<片名> 观众评价", "<片名> 专业影评"])
# 选择片名、年份/导演相符且可静态阅读的公开条目，而非搜索第一条。
fetch_webpage(url="<本次搜索返回的公开条目URL>")
# 页面访问被阻或身份不符：换公开文本来源；仍不可读就报告缺口。
```

## 分开读评分和观点

核对页面确实属于目标影片，再记录可见评分、评价人数和查询时点；评分人数很少或尚无评分时，不把数字说成稳定口碑。热门短评、最新短评和长影评不是同一抽样口径；只看到几条就说“所读评论中”，不能总结成“观众一致认为”。区分观众短评、个人长评和专业影评；找出具体赞扬和批评各自对应的可见来源，不能将单篇影评写成平台共识，也不将营销文案当真实观众评价。

只在来源允许使用且页面实际可访问的范围内核验，不绕登录、验证码、403/429，不批量采集或整段复制评论。用户自己提供的评论摘录可按请求概括。不同来源观点冲突时保留分歧，不拼造统一结论。

## 结束条件与返回

回答“值不值得看”时，用简短的适合人群、主要优缺点和剧透程度说明这是基于已读评论的归纳，不替用户决定。给出核对过的电影条目/影评链接、来源、查询时点和覆盖范围。若只找到简介、评分不可见或评论不可读，明确说哪些评价仍未核实，不拿猫眼排片或想看人数替代。证据已足够覆盖用户问题就结束，不为凑更多评论机械翻页。
