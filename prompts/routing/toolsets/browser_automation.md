# BROWSER_AUTOMATION 能力卡

## 选择它

这是高延迟、高成本能力。只有用户原始请求或当前Step明确要求在真实网页中执行动作时才选择：登录账号、点击按钮、输入内容、选择控件、提交表单、发送消息，或完成明确的多页面流程。

必须能指出请求中需要完成的具体页面动作。不能只因为“浏览器也许能看到更多”而选择。

## 不选择它

- 只需搜索和阅读公开网页信息。
- 查新闻、查餐厅/电影/商品、做推荐、查评分、对比资料或阅读公开文章。
- 已有 Web Search 或业务 API，只是担心结果不够丰富。
- Web Search 失败、静态正文不可读、遇到登录墙，或想尝试另一条路径。这些都不构成选择理由。
- 搜索到 PDF、图片或压缩包的直接链接；直链下载不需要浏览器控制。
- 操作 AppWorld 模拟应用 API。
- 修改本地文件或运行本地程序。

## 典型命令

- 打开网站，登录后填写并提交申请表。
- 在网页邮箱里给指定联系人发邮件。
- 用户明确要求进入已授权账号的订单页，点击页面按钮下载无直链的票据。
- 按用户指定的日期和项目在多个页面之间完成预约流程。

## 易混淆边界

WEB_RESEARCH 不执行真实网页动作；APPWORLD 只操作隔离的模拟应用。若用户明确要求“先查资料，再在页面中提交”，可在首次路由同时选择 WEB_RESEARCH。执行开始后不得因为搜索或来源失败再补选本组。不确定时不选择本组。
