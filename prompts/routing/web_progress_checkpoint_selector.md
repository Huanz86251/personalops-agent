你还要判断当前这个 Web Step 是否需要 Harness 在达到工具调用阈值后，强制插入一次结构化进度检查。这个判断只针对当前 Step，不要按整份用户请求泛化。

将 `require_progress_checkpoint` 设为 `true`，仅限以下情形：

- 学术、技术或政策深度研究，需要先找候选资料，再沿引用、方法、版本或原始来源继续核验；
- 当前 Step 内存在明确的串行依赖，后一步必须使用前一步新发现的实体、链接或结论；
- 任务预计需要多轮异构来源核对，且登录墙、页面阻塞、来源冲突或长链失败会显著改变后续路线。

设为 `false` 的情形：

- 开放时间、价格、地址、天气、人物简介、单项事实等普通查询；
- 三个关键词并发搜索、一次 API 批量查询或一次搜索后读取若干结果即可回答；
- 普通电影列表、场次或推荐，只要当前 Step 不要求“先发现影院，再逐家追查并完成订票链路”；
- 只是希望答案更丰富，但没有真正的前后依赖或高阻塞风险。

正例：

- “找近五年关于某算法的论文，先筛核心论文，再沿引用核对方法差异、实验设置和相互矛盾的结论。”填 `true`。
- “先找到某项政策的官方变更公告，再查变更前后的规定和实施数据，分析变化原因。”填 `true`。

反例：

- “查北京故宫明天是否开放、开放时间、票价和官方预约入口。”这些信息可并发搜索并读取官方页面，填 `false`。
- “查莱西明天有哪些电影并推荐两部。”若一次电影接口或一轮并发搜索足够，填 `false`；只有当前 Step 明确要求先发现影院、再逐家追查场次或订票阻塞时才填 `true`。

不确定、字段缺失或无法可靠判断时一律填 `false`。这个字段不改变能力组选择，也不能因为填 `true` 而多选工具组。
