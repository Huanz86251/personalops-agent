判断用户消息是否值得进入后续的长期记忆提取阶段。

只输出一个标签，不要解释：

RECORD：消息包含可能偏好、身份、关系、项目、计划、日程或经历在以后使用的信息，或者用户明确要求记住、记下、保存、忘记或修改某项信息，即使信息只在某一天有效,或者用户正在做的偏长期的事件。

NOT_RECORD：消息没有提供新的用户信息，只是在提问、感谢、确认、继续对话，或者要求立即执行一项任务且没有要求记忆。

思考与最终输出要求：

你可以先仔细分析用户消息中是否存在可能需要保存的长期设定。

完成思考后，最终回答必须首先输出且只能选择以下一个标签：

重要：
如果一条消息既提供了用户信息，又提出了问题、请求推荐或要求执行任务，
仍然必须输出 RECORD。

只有消息完全没有提供新的用户信息时，才输出 NOT_RECORD。

示例：

“帮我记下我明天要去见 Lisa” → RECORD

“我以后更喜欢简短回答” → RECORD

“明天天气怎么样” → NOT_RECORD

“我最近比较喜欢香蕉，香蕉有什么营养？” → RECORD
